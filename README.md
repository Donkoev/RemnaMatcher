# RemnaMatcher

Антифрод для [Remnawave](https://remna.st) (панель 2.7.x): детектит юзеров, которые вытаскивают vless-ключи из подписки и раздают их другим. Поведенческий скоринг, веб-панель в фирменном стиле Remnawave, уведомления и кнопки действий в Telegram. Проверено в бою на панели с 35 000+ юзеров и 9 нодами.

## Как это работает

**Сбор.** Коллектор раз в `POLL_INTERVAL_SEC` последовательно опрашивает ноды через тот же API, что и штатный «Обозреватель сессий» (`POST /api/ip-control/fetch-users-ips/{nodeUuid}`), и складывает наблюдения `юзер → IP → lastSeen` в SQLite. Отдельно синхронизируются справочник юзеров (включая HWID-лимиты), снапшоты трафика и репорты торрент-блокера. **Коллектор строго read-only** — панель он не меняет.

**Гео.** Оффлайн-базы DB-IP Lite (город + ASN), города лениво уточняются через ipinfo.io: сначала анонимно, при исчерпании лимита — по токену. Уточнение кэшируется навсегда. Логотипы провайдеров тянутся по фавиконкам (gstatic → DuckDuckGo → Яндекс → сайт провайдера) и кэшируются на диске.

**Скоринг.** Каждый цикл по активным IP (окно активности настраивается; Xray держит сессии «действительными» дольше реального, поэтому фильтр по lastSeen обязателен) считаются сигналы — в порядке приоритета:

| Сигнал | Очки | Логика |
|---|---|---|
| Много одновременных IP | +40–60 | порог **персональный**: HWID-лимит юзера × запас на устройство; для юзеров без лимита — общий порог |
| Всплеск трафика | +30–55 | средняя скорость за час выше порога, выше двойного — усиленный |
| Одновременно с разных провайдеров | +25–50 | считается только при превышении порога числа IP |
| Одновременно из разных стран | +15–30 | слабый сигнал: подписку легально делят друзья |
| Подключения из датацентров | +20–35 | у обычного юзера не бывает IP хостингов |
| Ловится торрент-блокером | +10–20 | блокировки штатным торрент-блокером панели за сутки |

Гео-«перемещения» (impossible travel, разные города) **намеренно не используются**: CGNAT мобильных операторов геолоцируется скачками, а подписку легально делят из разных городов.

Сумма → очки фрода → уровень: 🟢 → 🟡 → 🟠 (уведомление в TG) → 🔴. В интерфейсе показывается «утечка · N%» — вероятность, нормированная на красный порог. Очки затухают с настраиваемым полураспадом; система помнит, **какие** проверки сработали, пока их очки не растаяли (состояние «было» в отчёте — видно, почему уровень держится, даже когда текущие проверки чистые). Все пороги, окна и веса крутятся на странице «Настройки» без перезапуска.

**Действия** — только по явной кнопке (веб или TG) с подтверждением: revoke ключей (утёкший vless умирает, легитимный юзер обновится по ссылке подписки), отключение, сброс соединений, белый список. Всё журналируется. Юзеры из белого списка не попадают на главный экран и не шумят в TG.

**Telegram.** Алерты при выходе юзера на 🟠/🔴 с кнопками действий, кулдаун на повторы, сводный дайджест вместо спама при волне инцидентов, устойчивость к 429.

## Установка на сервер

Интерактивный установщик: спросит адрес панели и токены, поднимет всё в Docker.

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/Donkoev/RemnaMatcher/main/install.sh)
```

Панель поднимается на `127.0.0.1:3300` (у неё своя авторизация — пароль задаётся при первом входе; наружу доступ через SSH-туннель или свой reverse-proxy). Повторный запуск установщика обновляет код без потери конфига.

## Запуск (dev)

```bash
npm install
npm run dev:server   # API + коллектор + бот, порт 3300
npm run dev:web      # веб-панель, http://localhost:5173
```

По умолчанию `MODE=mock` — генерируются случайные юзеры с фродерами, можно тыкать всё без риска. У мока своя БД, боевые данные не трогаются.

## Боевой режим

1. Скопируй `server/.env.example` в `server/.env`, поставь `MODE=live` и заполни:

| Переменная | Что это |
|---|---|
| `REMNAWAVE_URL` | адрес панели |
| `REMNAWAVE_TOKEN` | API-токен панели (отдельный — отозвать можно в любой момент) |
| `REMNAWAVE_SECRET` | секрет nginx-защиты панели в формате `key=value`, если она есть (шлётся query-параметром и кукой) |
| `TELEGRAM_BOT_TOKEN` | токен от @BotFather |
| `TELEGRAM_ADMIN_CHAT_ID` | напиши боту `/start`, возьми свой chat id |
| `IPINFO_TOKEN` | опционально — токен ipinfo.io для уточнения городов (бесплатный тариф — 50k/мес; без него тоже работает) |

В `.env` живут только адреса, токены и пути. Периоды опроса и синхронизации, хранение данных и все окна/пороги правятся на странице «Настройки» панели на лету, без перезапуска.

2. GeoIP-базы (оффлайн, DB-IP Lite): `npm run -w server geoip`.
3. На нодах должен быть включён сбор сессий (`cap_add: NET_ADMIN` в docker-compose remnanode) — если «Обозреватель сессий» в панели работает, всё уже ок.

## Структура

- `server/src/remnawave/` — клиенты API панели: `http.ts` (чтение и действия разделены по классам), `mock.ts`
- `server/src/collector/` — опрос нод, синк юзеров, торрент-репорты, ретеншн
- `server/src/scoring/` — правила (`rules.ts`) и движок с затуханием и памятью срабатываний (`engine.ts`)
- `server/src/geo/` — GeoIP/ASN, детект датацентров, ленивое уточнение городов (`refine.ts`)
- `server/src/alerts/telegram.ts` — бот (grammY): алерты, дайджесты, кнопки действий
- `server/src/api/` — REST + SSE для веба, кэширующий прокси логотипов провайдеров
- `web/` — React + Vite + Mantine 7, тема портирована из remnawave/frontend
